# 轮趣四轮差速机器人使用文档

> 本文只讲日常使用：检查、建图、保存、定位、导航、上位机控制和停止。
> 安装与改代码见《开发实施文档》，话题和参数见《详细信息表》。

## 1. 开机检查

登录 NX：

~~~bash
ssh <SSH_USER>@<NX_MANAGEMENT_IP>
source ~/livox_fastlio/devel/setup.bash
~~~

检查雷达：

~~~bash
ip -4 addr show dev eth0
ping -c 2 192.168.1.165
~~~

检查底盘：

~~~bash
lsusb
ls -l /dev/ttyACM0 /dev/wheeltec_controller
~~~

通过条件：

- eth0 包含 192.168.1.5/24；
- 雷达 192.168.1.165 可达；
- /dev/wheeltec_controller 指向 ttyACM0；
- 急停可用，车辆周围安全。

## 2. 建图

### 2.1 启动

地图名不要使用空格：

~~~bash
roslaunch wheeltec_system_bringup wheeltec_mapping.launch \
  map_name:=factory_a
~~~

### 2.2 检查频率

另开终端：

~~~bash
source ~/livox_fastlio/devel/setup.bash
rostopic hz /livox/lidar /livox/imu /Odometry \
  /cloud_registered /odom
~~~

| 话题 | 期望 |
|---|---:|
| /livox/lidar | 约 10 Hz |
| /livox/imu | 约 200 Hz |
| /Odometry | 约 10 Hz |
| /cloud_registered | 约 10 Hz |
| /odom | 约 20 Hz |

### 2.3 驾驶采集

- 低速、匀速；
- 避免急刹和高速原地旋转；
- 从不同方向覆盖门口、墙面、拐角；
- 尽量形成闭合路线；
- 避免人员在雷达前长时间停留；
- 雷达松动后必须停止，本次地图不可继续使用。

### 2.4 停止并保存

建图过程中，过滤后的静态 PCD 每 30 秒自动保存一次。完成采集后，在建图终端按一次 `Ctrl+C` 并等待节点正常退出；退出时会再保存一次。不要使用 `kill -9`，不要在保存时断电。

节点退出后，单独生成交付地图：

~~~bash
rosrun wheeltec_map_tools finalize_map.py factory_a
~~~

命令完成时应显示 `[DONE] map finalized`。该工具读取已经自动保存的 `filtered_camera_init.pcd`，并生成导航所需的全部 PCD、PGM 和 YAML 文件。

检查：

~~~bash
find ~/livox_fastlio/maps/factory_a \
  -maxdepth 1 -type f -printf '%f %s bytes\n' | sort
~~~

应有：

~~~text
filtered_camera_init.pcd
raw_camera_init.pcd
public_map.pcd
map_raw.pgm
map_raw.yaml
map.pgm
map.yaml
map_metadata.yaml
~~~

## 3. 定位

~~~bash
roslaunch wheeltec_system_bringup wheeltec_localization.launch \
  map_name:=factory_a
~~~

等待 FAST-LIO 初始化。在 RViz 使用 2D Pose Estimate：

1. 点击小车在地图中的大致位置；
2. 拖动箭头指向车头；
3. 查看实时点云是否与地图墙面、门框重合。

检查：

~~~bash
rostopic echo -n 1 /map_cloud/header
rostopic echo -n 1 /cloud_registered_base/header
rosrun tf tf_echo map base_link
~~~

通过：

~~~text
map_cloud.frame_id = map
cloud_registered_base.frame_id = base_link
map→base_link 连续
~~~

启动最初数秒 TF 未连接通常是 IMU 初始化；持续断开才是故障。

## 4. 导航

定位成功后，另开终端：

~~~bash
roslaunch wheeltec_navigation navigation_teb.launch \
  map_name:=factory_a
~~~

发送目标前检查：

~~~bash
rostopic hz /odom
rostopic info /cloud_registered_body
rosrun tf tf_echo map base_link
~~~

必须满足：

- map_name 与定位一致；
- /odom 约 20 Hz；
- move_base 订阅 /cloud_registered_body；
- map→base_link 稳定；
- 急停可用；
- 已通知现场人员车辆将运动。

在 RViz 使用 2D Nav Goal。首次在新地图只发送短距离、开阔区域目标。

当前软件限制：

| 项目 | 值 |
|---|---:|
| 前进 | 0.35 m/s |
| 倒车 | 0.15 m/s |
| 角速度 | 0.80 rad/s |
| 线加速度 | 0.20 m/s² |
| 角加速度 | 0.30 rad/s² |

## 5. 上位机 ROS

上位机与 NX 在同一网络：

~~~bash
export ROS_MASTER_URI=http://<NX_MANAGEMENT_IP>:11311
export ROS_IP=<上位机IP>
~~~

读取：

~~~bash
rostopic echo /odom
rostopic echo /imu
rostopic echo /PowerVoltage
~~~

人工控制只使用 linear.x 和 angular.z，linear.y 必须为 0。

运动前必须告知现场，清空车辆周围并准备急停。

低速示例：

~~~bash
rostopic pub -r 10 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
~~~

按 Ctrl+C 后发布零速度：

~~~bash
rostopic pub -1 /cmd_vel geometry_msgs/Twist \
  '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
~~~

## 6. 停止顺序

1. 停止发送目标或人工速度；
2. 发布一次零速度；
3. 停止 navigation；
4. 停止 localization；
5. 建图模式先正常 Ctrl+C 停止并等待自动保存，再运行 finalize_map.py；
6. 用 rosnode list 确认业务节点已退出；
7. 最后关闭底盘和雷达供电。

## 7. 快速排错

| 现象 | 首先检查 |
|---|---|
| 无雷达点云 | eth0、192.168.1.165、网线、/livox/lidar |
| 无底盘 odom | lsusb、ttyACM0、udev、USB 供电 |
| FAST-LIO 无输出 | /livox/lidar、/livox/imu、初始化日志 |
| 点云直行时升降 | base_link→body 的 Pitch、雷达是否松动 |
| NDT 不收敛 | 地图名、初值、base_link 点云、外参 |
| TF 持续断开 | TF 唯一发布者、节点存活、系统时间 |
| 有路径车不动 | /cmd_vel、/odom、串口、急停 |
| 地图文件不全 | filtered_camera_init.pcd 是否存在、finalize_map.py 输出、目录权限和磁盘 |

## 8. 安全规则

- 未通知现场人员，不发布非零 /cmd_vel；
- 首次测试使用约 0.05 m/s 和数秒级时间；
- 不在台阶、斜坡边缘和人员密集区域首次测试；
- 定位未收敛时不发送导航目标；
- 雷达或外参变化后不使用旧地图；
- 测试结束必须发布零速度。
